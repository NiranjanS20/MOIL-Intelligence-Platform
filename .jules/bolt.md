## 2024-10-04 - [React State Update Batching with Promise.all]
**Learning:** Found multiple independent `useEffect` hooks in `MineWorkspace.tsx` that were triggering separate `setState` calls when their API requests resolved. In React, asynchronous state updates from different promises are not automatically batched (prior to React 18's automatic batching, and even then, aggregating is cleaner), leading to cascading re-renders and potential race conditions with shared state properties.
**Action:** Consolidate independent data fetching requirements for a single view into a single `Promise.all` block. This reduces rendering CPU overhead, creates deterministic state resolution (preventing race conditions when multiple endpoints populate the same object), and keeps code cleaner.
